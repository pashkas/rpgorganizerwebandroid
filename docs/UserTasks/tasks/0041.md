# Полоса изменений: ложный тик уровня 0→1 и скрытая полоса на точной границе level-up

## Запрос пользователя
«Если увеличивается опыт, а уровень персонажа не меняется, почему-то всё равно он меняется с 0 до 1.»
«Если какой-то навык даёт ровно столько опыта, что доходит сразу до следующего, полоску с изменениями почему-то не показывает.»

## Подход
1. **Тик уровня без level-up.** В простой `else`-ветке `setpercentage` (`pers-changes-item`) при `item.lvl != null` всегда вызывался `tickLevel(toLvl-1, toLvl, ...)`. Но `item.lvl` ставится и для exp/abil/cha-значений в пределах одного уровня (там `expChanges`/`abilChanges` ровно с 1 сегментом). Решение: тикать только при дискретном переходе уровня, т.е. когда `expChanges.length == 0 && abilChanges.length == 0` (chaLvl/abLvl-стиль). Для одиночных сегментов уровень не менялся — тик не нужен.
2. **Полоса скрывалась на точной границе.** Внешний `ChangesModel` для exp использует диапазон `afterPers.prevExp..afterPers.nextExp`. Если опыт пришёл ровно на границу: `beforeExp` ниже диапазона → `valFrom` клампится в 0; `afterExp == afterPers.prevExp` → `valTo == 0`. Шаблон `*ngIf="valFrom != valTo"` прятал весь блок, и сегментная анимация (которая по `expChanges` нормирует сама) даже не запускалась. Решение: пропускать блок, если `expChanges.length > 1 || abilChanges.length > 1` — мультисегмент означает реальный level-up. Аналогично снят ранний `return` в `setpercentage`.

- `src/app/pers-changes-item/pers-changes-item.component.html` — `*ngIf` контейнера
- `src/app/pers-changes-item/pers-changes-item.component.ts` — `setpercentage` (ранний return + блок `tickLevel`)
