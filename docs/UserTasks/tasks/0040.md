# Покупка перков на ОН при отключённых ОП

## Запрос пользователя

> «Я хочу, что если настройка в gameSettings - выключены очки перков, чтобы перки покупались на очки навыков. Стоимость перка - сколько за уровень ОН получают, полная стоимость как у навыка, но даём докачивать. И при активации перка он не прыгает сразу на последний уровень, а на пятый. Сколько опыта дается за задачу перка — пол-прокачаный давал 5. В changes если перки отключены надо ОН с двух сторон показывать.»

## Подход

В режиме `isPerkPointsEnable=false` перк ведёт себя как обычный навык по экономике, но прокачивается шагом `maxAbilLvl/2` (активация → 5 → 10).

- `EraSettings.abCost` для перка при ОП-выкл: `abPointsPerLvl * hardness` (=5 ОН за клик), вместо хардкода `5`.
- `EraSettings.abTotalCost` уже возвращал `curLvl * hardness` для перка при ОП-выкл — оставлено. Теперь сходится с `abCost`, т.к. value не прыгает 0→10.
- `EraSettings.checkPerkTskValue`: при ОП-выкл выходим до нормализации `tsk.value = maxAbilLvl` — даём держать промежуточное value=5.
- `EraSettings.abChangeExp` для перка: `return curLvl` (вместо `curLvl > 0 ? maxAbilLvl : 0`). Пол-прокачаный (5) даёт 5, полностью (10) — 10.
- `pers.service.upAbility`: для сложн-перка при ОП-выкл шаг = `maxAbilLvl/2` (активация на 5, докачка до 10). Норм-перк / сложн-перк при ОП-вкл — без изменений.
- `level-up-msg.component.html`: убрана инверсия `!isPerkPointsEnable` у блока ОП (теперь показывается, когда ОП включены). Добавлена левая колонка с алмазом+ОН для случая ОП-выкл — попап симметричный.

«Принуждение докачать» в `recountAbilMayUp` (Шаг 3, `isStartedHardPerk`) уже включало перк при ОП-выкл с `0 < value < maxAbilLvl` — оставлено.

## Затронуто

- `src/app/game-settings/EraSettings.ts` — `abCost`, `abTotalCost`, `abChangeExp`, `checkPerkTskValue`.
- `src/app/pers.service.ts` — `upAbility`.
- `src/app/level-up-msg/level-up-msg.component.html` — правая+левая колонки.

## Побочные эффекты

- Старые персонажи с прокачанным перком value=10 — без изменений: `abTotalCost = 10*1 = 10`, как и раньше.
- В режиме `isPerkPointsEnable=true` ничего не должно поменяться: все правки идут под условиями `!isPerkPointsEnable` либо общие (`abChangeExp` стал `curLvl`, что для value=10 даёт ту же maxAbilLvl=10).
