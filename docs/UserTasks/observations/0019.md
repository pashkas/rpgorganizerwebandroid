# Переключатель isPerkPointsEnable — чек-лист мест разветвления

## Суть

Флаг `GameSettings.isPerkPointsEnable` переключает экономику перков между «отдельный пул ОП» и «перки на ОН как навыки». Логика разветвлена по 10+ местам — при балансных правках надо проверять весь список, чтобы не разъехалось.

## Где в коде

- `src/app/game-settings/EraSettings.ts`:
  - `abCost(curLvl, hardness, isPerk)` — `0` при ОП-вкл+перк, `abPointsPerLvl*hardness` при ОП-выкл+перк.
  - `abTotalCost(curLvl, hardness, isPerk, _)` — `0` при ОП-вкл+перк, `curLvl*hardness` иначе.
  - `perkCost(_, _)` — `1` при ОП-вкл, `5` при ОП-выкл (вызывается только из ОП-вкл-ветки `recountAbilMayUp`).
  - `checkPerkTskValue(tsk)` — при ОП-вкл нормализует `value` на `maxAbilLvl`, при ОП-выкл оставляет промежуточное value (поддержка докачки 0→5→10).
- `src/app/pers.service.ts`:
  - `upAbility` — для сложн-перка при ОП-выкл шаг `maxAbilLvl/2`, при ОП-вкл `value += 1`.
  - `recountAbilMayUp` Шаг 1: при ОП-выкл `op = on`, и для перка проверяется `on < abCost`; при ОП-вкл — `op < perkCost`.
  - `recountAbilMayUp` Шаг 3 (`isStartedHardPerk`): включает перк при ОП-выкл с `0<value<maxAbilLvl`.
  - `getClassicalAbPoints` — `perkLvls = 0` при ОП-выкл (все уровни идут в ОН).
  - `getClassicalPerkPoints` — возвращает `0` при ОП-выкл (`prs.OP = 0` всегда).
  - `recalc` строки ~1914-1917: `opValTotal` накапливается всегда, но `getClassicalPerkPoints` при ОП-выкл его игнорирует.
- Шаблоны:
  - `pers-list.component.html` — бейдж ОП скрыт при ОП-выкл.
  - `task-detail.component.html` — бейдж ОП скрыт при ОП-выкл.
  - `characteristic-details.component.html` — бейдж ОП скрыт; кнопка апа перка проверяет `pers.ON > 0` при ОП-выкл вместо `pers.OP > 0`.
  - `level-up-msg.component.html` — звезда ОП показывается при ОП-вкл, левая колонка ОН — при ОП-выкл (симметрия).

## Почему важно

`isPerkPointsEnable` — не просто «вкл/выкл валюту»: это фактически два разных режима с разными формулами и разной разметкой. При любой балансной правке (новый коэффициент, изменение стоимости, переименование поля) пройдись по списку — обычно правка нужна в обеих ветках, иначе одна из конфигураций молча уезжает в минус по балансу или ломает UI. Список мест почти полный — наблюдение играет роль чек-листа.
