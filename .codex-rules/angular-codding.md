# Angular Coding

Применяй при изменении Angular-компонентов, сервисов, forms, RxJS и API clients. Перед правкой прочитай `.codex-rules/coding.md` и `.codex-rules/frontend-coding.md`; версия Angular и локальный стиль проекта имеют приоритет.

## Components

- Разделяй smart и dumb components только когда это делает поток данных понятнее: smart загружает данные, dumb получает `@Input` и сообщает события через `@Output`.
- Создавай standalone components только в проекте, который уже использует этот подход.
- Выбирай `inject(...)` или constructor injection по версии и стилю проекта; не смешивай подходы без причины.

## RxJS

- Держи stream читаемым; называй промежуточные streams, если длинная pipeline скрывает сценарий.
- Используй `subscribe()` в компоненте для side effect. Данные в шаблон передавай через `async` pipe, когда это подходит.
- Для отписки используй `async` pipe или принятый проектом механизм. `takeUntilDestroyed()` применяй только в совместимой версии Angular.

## Forms And Templates

- Для сложной формы используй reactive forms, для простой — template-driven forms, если проект не задаёт другой стандарт.
- Не размещай в template тяжёлые вычисления и вызовы дорогих методов.

## Files

- Файлы компонента `.ts`, `.html` и `.scss` держи рядом, если так организован проект.
- Константы оставляй рядом с использованием; общий constants-файл создавай только для общего контракта.

## Completion

- Если проверка разрешена проектом или пользователем, проверяй Angular-код через Angular compiler с `--noEmit`; IDE-инспекции не заменяют эту проверку.
- Проверь, что новые API доступны в версии проекта, у каждой ручной подписки есть понятный lifecycle, а UI-ветка завершена по критериям `frontend-coding.md`.
